# データ集合ツール（Data Collector）v1.0 — 操作マニュアル

[← nTools トップへ](../../README.md)

![データ集合ツールのアイコン](../../scripts/ntools/icons/collector.png)

> [!WARNING]
> **実行前に必ずシーンを保存し、重要なデータを別媒体にもバックアップしてください。** 本ツールはMaya 2027用の試験的な補助ツールです。すべての外部依存ファイルを検出・修正できるわけではありません。**卒業制作や提出データでは、最後に別PCで必ず開いて検証してください。**

## 何をするツール？

制作中のMayaシーンから、**現在のMayaプロジェクトの外側**にある外部ファイルを調べ、選択したものをプロジェクト内にコピーし、Mayaシーンのリンクを新しい場所へ変更します。元の外部データは削除しません。

授業では、**最終提出直前**にプロジェクトを整理するために使うことを想定しています。

### 基本操作（3ステップ）

1. **File → Set Project** で提出するプロジェクトを選択。**File → Save Scene** でシーンを保存してください。
2. nToolsシェルフの **「集合！」（ホイッスル）** をクリック。プロジェクト外の参照一覧が出ます。コピーする項目はチェックON（コピー可能な項目は初期状態で全チェックON）。無視するものはチェックを外してください。
3. **「選択したデータを集合！ コピー ＋ リンク更新」** を押し、容量と件数の最終確認後に実行します。完了したら再スキャンし、ビューポートやレンダリングで問題ないことを確認してシーンを**保存**してください。

> **再スキャンの結果が0件でも「すべての依存が完全に収集された」ことを意味しません。** 下記の非対応例を確認してください。

## ツール画面の読み方

| 欄 | 説明 |
|---|---|
| 選択 | コピー対象を指定。コピー可能な項目は最初からチェックON |
| 種類 | `texture`、`reference`、`standin`、`alembic`、`gpu`、`ncache` など |
| ノード | Mayaシーン内でファイルパスを持つノード名 |
| 状態 / 元ファイル | 元データの場所。存在しないファイルや参照シーン内の変更禁止ノードはチェック不可 |
| 一覧を再スキャン | 現在のシーンの状態から最新の外部パスを再検出 |
| 全てチェック / 全て解除 | コピー可能な項目のみ一括選択 |
| Help / 使い方 | このページをブラウザで開く |

## 対応ファイル・配置先

既存のプロジェクト構成をなるべく尊重して、用途別のフォルダ配下に `nToolsCollected/` を作ります。同名ファイルが違う場所に存在する場合は、取り違えを防ぐため**元フォルダ単位で別のサブフォルダ**に分けます。

| 対応対象 | プロジェクト内のコピー先（例） |
|---|---|
| `file` / `aiImage`、通常テクスチャ、UDIM、画像連番 | `sourceimages/nToolsCollected/` |
| Image Plane | `sourceimages/nToolsCollected/` |
| Arnold Stand-in `.ass`（`aiStandIn.dso`） | `scenes/standins/nToolsCollected/` |
| Maya参照シーン `.ma` / `.mb` | `scenes/references/nToolsCollected/` |
| Alembic `.abc` | `cache/alembic/nToolsCollected/` |
| GPU Cache | `cache/gpuCache/nToolsCollected/` |
| nCache（XMLとキャッシュ本体） | `data/nCache/nToolsCollected/` |
| USD Proxyの参照ファイル | `scenes/usd/nToolsCollected/` |
| Arnold Volume | `cache/volumes/nToolsCollected/` |
| 音声 | `sound/nToolsCollected/` |

保存例：

```text
MyMayaProject/
├── workspace.mel
├── scenes/
│   ├── shot01.ma
│   ├── references/nToolsCollected/87cc90.../character.ma
│   └── standins/nToolsCollected/24f45d.../tree.ass
├── sourceimages/nToolsCollected/702b33.../
│   ├── wall.1001.exr
│   └── wall.1002.exr
├── cache/alembic/nToolsCollected/47fabc.../walk.abc
└── data/nToolsCollected/reports/
    ├── shot01_日時.ma              ← 実行前のシーンのバックアップ
    └── collect_日時.json          ← コピー・リンク変更の記録
```

**元ファイルは移動しません。** 既存のコピー先に異なる中身の同名ファイルがある場合、上書きせず新しいサブフォルダを作成します。一般的な画像・テクスチャや音声のリンクは可能な限りプロジェクト相対パスに変換します。一方、**参照シーンはMaya公式仕様上相対パスに対応していないため、絶対パスで再リンクします。** 参照を含むプロジェクトを他のPCに移す際は、Reference Editorで参照パスの再設定が必要になる場合があります。

## 安全に使うための仕様

- シーンが未保存、変更済み、プロジェクト未設定の場合は実行しません。
- コピー元を残し、**元のシーンのバックアップ**を作ってから変更します。
- コピー後はSHA-256でファイル内容の一致を検証します。コピーとリンク更新は別々の段階で行います。
- リンク更新に失敗した場合、変更済みのリンクを元に戻す処理を試み、新たに作ったコピーを取り除きます。**完全な復元を保証するものではありません。**
- 自動保存はしません。結果を確かめたうえでユーザーがシーンを保存してください。
- 一度の処理でファイル数20,000、容量50GiBの上限を設けています。実行前にディスク空き容量を確認します。

## 必ず理解しておきたい制限事項

1. **Arnold `.ass` の内部依存**：`aiStandIn.dso`が指す`.ass`ファイル自体はコピーできますが、`.ass`内の別のテクスチャやキャッシュの絶対パスは書き換えません。Arnoldを使って実際にレンダリングを確認してください。
2. **参照シーン内部**：読み込み済みのトップレベル `.ma/.mb` 参照パスの変更は再読込を伴って試みますが、参照シーン内に記録された外部依存を完全には書き換えません。参照シーン内のノード、入れ子参照、未ロードの参照は安全のため自動変更しません。
3. **USDレイヤー内部**：外側のUSDファイルは対象ですが、USD内部のサブレイヤー・参照・外部テクスチャまでは再帰解析しません。
4. **プラグイン固有のキャッシュ**：Bifrost、XGen、Yeti、MASH独自出力、V-Rayなどは独自の参照形式を持つため、すべてのパスは収集できません。専用の書き出し・パッケージ化機能を使用してください。
5. **ネットワーク上で失われたファイル**：元データが存在しない場合は一覧に表示しますが、自動で作り出せないのでチェック不可です。
6. **他OSへの移動**：Windows専用のドライブレターやMac専用ボリュームのパス、未対応のパス表現では正しく検出できないことがあります。
7. **ライセンス**：SketchfabやFabなどから取得した素材の再配布が禁止されている場合があります。プロジェクトにコピーして他人へ渡す前に、ライセンスを確認してください。

## よくある質問

**Q. なぜ全ての項目が見つからないのですか？**  
Mayaやプラグインの参照先は多様です。この版では対応ノードのファイルパスのみを調べ、特殊な内部参照は表示対象外です。Mayaの `Windows → General Editors → File Path Editor` も併用してください。

**Q. 他のPCへプロジェクトをコピーすれば必ず動きますか？**  
いいえ。画像・テクスチャの一般的なリンクは相対パスにしていますが、Mayaリファレンスや一部プラグインのキャッシュは絶対パスが残ります。提出前に別PCで検証し、必要なパスを手動で修正してください。

**Q. 実行後、Mayaを再起動する必要はありますか？**  
通常のテクスチャなどは不要です。ただし一部のプラグインキャッシュや参照シーンの再読込が必要な場合があります。必ず結果を確認してください。

**Q. 出力先のフォルダ名が数字や英字なのはなぜ？**  
元のディレクトリをハッシュ化して、同じ名前の素材を誤って上書きしないためです。

**Q. 何も表示されません。**  
現在のプロジェクト内にすべて配置されているか、対応ノードに外部リンクがない可能性があります。未保存の素材や埋め込み依存については別途確認してください。
